## field not read by the import

each top level section has its own import mapper that reads a field by its json_fields const, so a field that the mapper of that section does not read is silently dropped: the data of the field is never imported and nothing is reported, because a key that is not read is simply not looked at; the section decides, so "description" is read for a word and dropped for a value; the allowed fields are read out of the php source of the mapper and of its parents, so this list never ages; checked are the top level keys and the keys of the entries of a top level list. a finding does not say that the file is wrong: where the export writes the field (e.g. "row" and "column" of a component), the file is right and the mapper is the side that does not read it yet
