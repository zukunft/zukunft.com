## Lessons learned by llm

- A check that turns a warning into an error (`db_object::name` in the step of the coding rule checks, the read without
  connection of `sql_db::fetch` in the second step of prompt 5) makes the hidden callers visible in the next run; before
  such a change, search the callers of the function and fix the ones that rely on the old warning, or name them as the
  expected effect in the report, because the developer otherwise sees the errors as a regression of the change.
- The function name of an internal error log is taken from the first frame of the trace, which is the log function
  itself, so an error that the developer has to trace back must name its caller in its own text (see
  `sql_db::connection_lost_text`).
- Read the caller chain to its last entry before naming the reader: the chain of the user export ended with
  `user_tests->run` and not with `assert_json_file`, so the fix went to the wrong caller first; a chain names the
  place of each call too, because one test function has several calls of the same function.
- A unit test with a commented assert still runs its call: the FOAF block of `phrase_list_tests` read the database in
  the unit tier without any check, which only the read without connection made visible; a call whose assert is a
  TODO belongs in the tier of what the call does, so that it is ready when the assert is activated.
- A setter with a conversion as side effect (`expression::set_ref_text` converts to the user text) can read the database
  in a code path that is meant to work on preloaded data only; a caller that needs only one format sets only that one
  (`set_ref_and_user_text($ref, null)`).
- A load with a cache must not query when the cache has everything (`phrase_list::load_by_ids`), and an id comparison
  must use the same id kind on both sides (phrase ids against term ids in `expression::load_result_phrases`); the read
  without connection of the unit tests found both, although they are needless queries of every calculation.
- A unit test whose expected text contains a "not found" message of a lookup tests the missing database of the unit
  tier, not its subject; it sets up the subject without the lookup instead (the empty reference text test).
- A step that shifts the database ids e.g. a new config key also renames every snapshot whose file name holds a moved
  id, so its report names this effect upfront; a snapshot of a late imported object is named by a stable key instead
  of its id.
- A new function is tested by a direct call, not only through its caller, because the generated test coverage report
  counts the direct calls; and replacing the last test call of a function (`set_ref_text` in `expression_tests`) makes
  it untested, so the replacement keeps one direct test of it.
- The diff of a generated file is a character diff that shows only the changed characters of a number, so before
  calling it a regression compare the full lines of the file with the previous version, e.g. "+2" was 1834 becoming
  1832; and a check of a generated file fails once after each test change, so it is no defect if the next run passes.
- An id const of a csv row (`user_statuum::READ_ONLY_ID`) is checked against the csv before a test relies on it,
  because the consts are written by hand and nothing compares them with the rows; a factory that no test calls hides
  the same defect (`test_types::user_status`).
- A test that converts a reference text back to the user text uses the term list that has created the reference ids;
  `term_list_for_tests` numbers its terms from one, so its ids match no reference text of the real test terms.
- Before saying a failure has a single cause, check every failing case: the reads of two cases hid that the other three
  failed for a different reason (the `> 0` of `get_usr_text`); a new round trip test is compared in the form the
  conversion writes (here without spaces), not in the typed form.
- A leftover row is decoded fully and compared with what the test removes, phrase by phrase: the missing year of
  the leftover result showed that it was the copy without time of `result::save_if_updated`, not the result itself.
- A ratchet const is set to the count that its own check computes (here the same as `git grep`), never to the old
  const minus the solved ones, because the old const may already be wrong; a difference between the count and the old
  const is reported, not explained by a guess.
