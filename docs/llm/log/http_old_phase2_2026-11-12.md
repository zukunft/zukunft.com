### Request

Remember the last used source and verb of a user and preselect them in the value and the triple add form, as the
retired `http_old/source_add.php:119`, `source_edit.php:106`, `value_add.php:129` and `verb_edit.php:115` did.
Decisions of the developer:
1. the last used source / verb of the user is set both after a confirmed add or change of a source / verb and
   after a value saved with a source / a triple saved with a verb
2. it is set in the write of a user request, never in `source::save`, `verb::save`, `value::save` or
   `triple::save`, because the imports call those for every object; a confirmed frontend change writes through
   `frontend::action_crud` → `db_object::add_via_api` / `db_object::update` (`web/sandbox/db_object.php:926`,
   `:963`), which convert with `MapObject::convertToDb` and call the backend save directly; this path is covered
   with one shared function
3. writing the last used source / verb creates no change log row: it is a convenience pointer, written with a
   dedicated update of only that field, not through the logged user save
4. the verb gets the db field `verb_id` in the users table like `user_db::FLD_SOURCE`, with the minor version raise
   and the upgrade of `db_check`, for Postgres and MySQL; `user::set_verb` (a stub) is replaced; the value add form
   (`web/value/value.php::source_selector`) preselects the last used source and the verb selector of the triple add
   form the last used verb, only if the new object has none yet; an object that has one keeps it

### Request

The export of a phrase selection that the retired scripts `get_json.php`, `json_save.php`, `get_xml.php` and
`get_csv.php` answered, as one backend api and as a download of the export views. Decisions of the developer:
1. one export api: `api/json` answers a GET with the phrases given by name (`url_var::WORDS`) or by id, with all
   related phrases (`phrase_list::are`), for the user of the request, only what the user may read
   (`is_readable_by`); a format url var selects json or xml (`json_io::export` resp. `xml::export_by_phrase_list`);
   no `api/xml`; the line `$wrd_id = 1` goes; a request without phrases gets a message; one openapi entry
2. (import, see the other log file)
3. decided by the lead (reduce to the max): the four export placeholder components (`ui_im_export::json_export`,
   `xml_export`, `csv_export`, `ods_export`) are removed from the views when the download replaces them; the ods
   export stays a gap (written down in `pending_prio_2.md`)

Checked before the plan, step 3: the csv of a value table (`value_list::table_to_csv`) does **not** cover the old
`get_csv.php`: it exports the value tables that a page shows, with a phrase as the column head, while `get_csv.php`
listed for each formula given by name its results; so the csv export adds the results of the formulas given by name.

## Lessons learned by llm

1. Before a new db field is planned, ask whether it can change a result and what it points to: a helper field of
   the workflow, which only changes a suggestion, is neither logged nor registered, a pointer to data that a user
   creates (a source) is logged, a pointer to a type that an admin confirms (a verb) is a helper field.
2. Never copy a phrase like "minor version raise" from `pending.md` into a brief without checking the launch state:
   before the launch of 0.0.3 a new db field goes into the setup sql and `db_upgrade_0_0_4`, never into a raise.
3. "Deprecate" asks for fewer lines: this phase added about 2200 lines and deleted no `http_old` script, which the
   developer had to correct; the brief states the line balance as the target and the gaps that may stay.
4. A new test of a class follows its existing callers, e.g. `$imp->usr` of an import; a fatal in a write test also
   skips its cleanup, and in the next run the leftover changes snapshots that the auto update writes as expected,
   so after a fatal the diffs of the next run are checked against the commit before any fix.
5. A negative read permission test uses `usr_normal`, because the profile `test` of `usr1` and `usr2` counts as
   system user and may read every object.
6. A new path const needs its namespace in `library::php_path_convert`, and every `use` needs a real include; a
   commented include does not pass the include check.
7. An agent never creates a log file on its own: one log per request of the developer, as this combined file shows.
